# 拼饭小程序基础工程设计

## 目标

在现有微信原生小程序项目上建立可持续开发的基础工程。项目继续使用微信当前的新架构能力，并将 Vant Weapp 作为默认界面组件库。

初始化完成后，项目应满足以下条件：

- 保留 Skyline 渲染引擎、glass-easel 组件框架、TypeScript 和 Less。
- 安装并锁定 `@vant/weapp@1.11.7`。
- 微信开发者工具能够正确构建 npm 依赖。
- 首页能够在 Skyline 下展示并操作代表性的 Vant 组件。
- 代码具备统一的格式、静态检查和类型检查命令。
- 项目结构和开发约定有简明文档可供后续开发遵循。

## 技术方案

采用微信原生小程序方案，不引入 Taro、uni-app 或其他跨端框架。

Vant Weapp 通过 npm 安装，并在各页面或组件的 JSON 文件中按需声明。业务代码直接使用 Vant 组件，不在初始化阶段为每个组件增加包装层。只有当后续出现明确、重复的业务语义时，才新增项目级业务组件。

项目继续使用以下现有配置：

- Skyline 渲染引擎。
- glass-easel 组件框架。
- TypeScript 编译插件。
- Less 编译插件。
- `lazyCodeLoading: "requiredComponents"` 按需注入组件代码。

Vant 官方未明确承诺所有组件都兼容 Skyline，因此初始化验证将覆盖不同类型的代表性组件。后续新增 Vant 组件时，也应在真机或开发者工具的 Skyline 模式下确认表现。

## 目录与职责

保留微信原生的页面和组件组织方式：

```text
miniprogram/
  components/     项目级可复用业务组件
  pages/          页面及其私有逻辑
  styles/         全局设计变量和公共样式
  utils/          无界面依赖的通用函数
  app.json        页面、渲染器和全局小程序配置
  app.less        全局样式入口
  app.ts          应用生命周期和全局状态入口
typings/          项目级 TypeScript 类型声明
docs/             项目说明和设计文档
```

初始化会移除微信模板自带的用户信息、启动日志等演示内容，但保留当前自定义导航栏，避免把导航体系改造扩大到本次基础工程范围。

## 界面基础

首页作为基础工程的验收页面，不承载正式业务功能。它用于确认以下能力：

- Vant 基础展示组件能够正确渲染。
- Vant 交互组件能够正确响应事件。
- Vant 弹层类组件能够正常打开和关闭。
- 全局主题变量能够影响 Vant 和页面样式。
- 安全区域、页面滚动和自定义导航栏能够协同工作。

主题变量统一放在全局样式文件中。首批变量只覆盖项目当前需要的颜色、文字、背景、间距、圆角和阴影，不提前建立庞大的设计系统。

## 编码规范

- TypeScript 保持严格模式，不使用无约束的 `any`。
- 页面状态和事件参数使用明确类型。
- 文件名和目录名使用小写短横线形式；TypeScript 变量使用驼峰形式。
- WXML 中循环必须提供稳定的 `wx:key`。
- Vant 组件按页面或组件声明，避免不必要的全局注册。
- 样式优先使用项目变量；业务页面不直接修改 Vant 源码。
- 页面只负责页面编排，可复用且具有独立业务含义的界面才放入 `components/`。
- 通用函数保持无界面依赖，放入 `utils/`。

项目采用以下检查工具，并避免让多个工具重复处理同一种文件：

- Biome 负责 TypeScript 和 JSON 的格式化及代码检查。
- TypeScript 编译器负责严格类型检查。
- Stylelint 负责 Less 样式规则检查。
- Prettier 配合 `prettier-plugin-mp` 负责 WXML 和 Less 格式化。

项目提供统一的格式化、自动修复和完整检查命令。完整检查命令必须覆盖上述工具，便于开发者本地运行，也便于后续接入持续集成。检查规则以发现真实问题为主，不添加与当前代码无关的复杂约束。

## 状态与数据流

本次初始化不接入后端，也不建立全局状态库。

验收页只使用页面本地状态：

1. 用户触发 Vant 组件事件。
2. 页面方法更新本地数据。
3. WXML 根据数据更新界面。

应用级全局数据保持最小化。正式业务出现跨页面共享需求后，再根据真实数据生命周期决定使用应用全局数据、缓存或独立状态模块。

## 异常与兼容处理

基础工程只处理真实的系统边界：

- npm 构建失败时，通过依赖安装和微信项目配置定位问题。
- Skyline 下组件表现异常时，先确认该组件的 WXML、样式和事件是否受渲染器限制。
- 不为尚未出现的兼容问题增加降级分支或旧渲染器适配层。

如果某个 Vant 组件在 Skyline 下确认不可用，后续针对该组件选择等价原生实现或小范围业务组件替代，不整体降级项目架构。

## 验证方案

初始化完成后执行以下验证：

1. 安装锁定依赖，并确认依赖树可重复安装。
2. 执行 TypeScript 严格类型检查。
3. 执行 Biome、Stylelint 和 Prettier 检查。
4. 构建微信小程序 npm 包，并确认 Vant 产物生成。
5. 在微信开发者工具中打开首页，检查控制台无错误。
6. 在 Skyline 下检查基础展示、点击事件、弹层开关、滚动和安全区域。
7. 在可用条件下进行一次真机预览，确认代表性组件的触摸和布局表现。

若本地环境无法自动控制微信开发者工具或真机，自动检查和 npm 产物验证仍必须完成，并明确列出需要人工执行的最后一项验证。

## 本次范围

本次包含 Vant 接入、基础目录、主题变量、代码规范、验收首页和相关说明。

本次不包含正式拼饭业务页面、后端接口、登录流程、支付、全局状态库、分包方案、自动发布流水线或完整业务组件库。
