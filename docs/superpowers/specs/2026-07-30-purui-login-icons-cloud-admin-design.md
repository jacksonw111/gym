# 普瑞健身登录、图标与云端后台设计

## 目标

本次改动解决三个问题：

1. 小程序不再把所有首次访问者默认创建为“新会员”，而是在用户主动购买或从“我的”点击登录时获取并保存微信资料。
2. 小程序和运营后台的主要导航与操作入口使用简洁、清晰的线性图标。
3. 运营后台部署到当前 CloudBase 测试环境的静态网站托管，测试与正式环境共用同一套业务代码。

本次不接入新的付费服务器，不自动启用超出免费额度的云资源，也不改变已有预约、课包、排班、反馈和申诉规则。

## 方案选择

### 采用：同一套代码，由环境配置决定连接目标

- 小程序、运营后台和云函数共享现有业务实现。
- 当前开发、体验和后台托管均连接测试环境 `cloud1-d1gmh1lu77f6e8c06`。
- 正式上线时只替换环境编号、域名、支付配置和服务密钥，不修改业务流程代码。
- 测试环境使用真实 CloudBase 数据库、云函数、云存储和微信授权，不使用模拟会员。

### 不采用：在业务代码中到处写死测试环境

这种方式当前操作少，但正式迁移时容易遗漏环境编号，并可能把测试支付或测试数据带入正式环境。

### 不采用：测试版和正式版维护两套代码或两个分支

两套实现会逐渐不一致，测试结果不能可靠代表正式版本。

## 游客与登录状态

### 游客打开小程序

- 小程序启动后可以取得云函数调用所需的微信身份，但不因此创建会员记录。
- 游客可以查看已上架课包、在职教练、价格和教练公开课程表。
- 游客不能购买课包、预约课程、查看个人课程、提交反馈或申诉。
- 云端 `bootstrap` 对未注册微信身份返回游客状态、公开课包和教练信息，不写入 `users` 集合。

### 主动触发登录

只有以下两种入口触发登录：

1. 游客在购买页选好课包和教练后点击“确认购买”。
2. 游客进入“我的”页面并点击“微信登录”。

应用启动、浏览首页、查看教练和查看价格时均不弹出授权。

### 登录页面

登录使用独立页面，包含三个明确步骤：

1. 使用 `button open-type="chooseAvatar"` 让用户主动选择微信头像。
2. 使用 `input type="nickname"` 让用户填写或选择微信昵称。
3. 使用 `button open-type="getPhoneNumber"` 让用户主动授权手机号。

页面明确说明资料用于会员识别、预约联系和教练服务。用户拒绝任一授权时保持游客状态，可以返回继续浏览，也可以稍后重新登录。

头像先通过 `wx.cloud.uploadFile` 上传到当前环境的云存储，保存得到的云文件地址。手机号授权结果只发送到云函数，由可信服务解析，客户端不能直接提交一个自称是微信手机号的字符串。

云函数在头像、昵称和手机号都准备好后，通过一次数据库事务创建会员；同一微信身份重复提交时更新原会员资料，不重复创建会员。

### 登录后的返回

- 从“我的”进入登录：成功后返回“我的”，展示头像、昵称、手机号和课包摘要。
- 从购买页进入登录：购买页保留已选课包和教练；成功后返回原页面，按钮提示“继续购买”。用户再次确认后才发起支付，避免页面跳转后自动调起支付。

## 云端接口与数据

### 用户资料

`User` 保留并实际使用以下字段：

- `id`
- `openId`
- `name`
- `avatarUrl`
- `phone`
- `roles`

未注册游客不创建占位 `User`，也不使用“新会员”作为默认昵称。

### 接口行为

- `bootstrap`：返回 `authenticated`、可选的 `profile`、公开课包和教练，以及登录用户自己的数据。
- `registerMember`：接收昵称、头像云文件地址和微信手机号授权凭证，使用服务端微信身份创建或更新当前会员。
- 购买、预约、取消、完成、反馈和申诉接口继续在服务端要求已登录会员。
- 教练和管理员身份仍来自已注册用户及后台绑定关系。
- 后台会员列表只显示真正完成登录的会员。

### 安全边界

- 用户身份只使用云函数上下文中的微信 `openId`，不相信客户端传入的用户编号。
- 手机号只使用微信授权凭证在云端解析。
- 用户只能更新自己的会员资料。
- 头像只接受当前 CloudBase 环境返回的云文件地址。
- 管理后台仍需管理员账号、密码和服务端会话；网页端的基础云身份不能替代管理员登录。

## 图标与界面方向

保持现有普瑞健身的暖色、力量感和清晰排版，不进行无关的整体重做。参考 Bakai Lab 的安静线性图标、紧凑控件和按压反馈：

- 小程序底部导航用首页、课程、我的、工作台和日历等线性图标替换字母或单字标记。
- 购买、返回、电话、时间、课包、预约、反馈和申诉等主要入口在文字旁增加图标。
- 使用项目中已有的 Vant Weapp 线性图标，避免新增远程图标请求和额外资源服务。
- 运营后台用本地内联线性图标替换侧栏的 `01`—`06` 数字标记。
- 重要操作保留文字标签，不把关键功能做成只有图标的按钮。
- 图标继承当前文字颜色，选中态使用现有品牌色，并提供明确的按压状态和无障碍名称。

## 运营后台云端部署

### 部署方式

- React/Vite 后台构建到 `admin/dist`。
- 使用 CloudBase 静态网站托管发布到 `/admin/`。
- `gym-api` 继续作为后台业务云函数。
- 数据库、云函数、静态托管和云存储全部位于当前测试环境。
- Vite 使用兼容子路径的资源地址，保证 `/admin/` 下的脚本和样式能正常加载。

项目现有 `cloudbaserc.json` 已声明网站插件、`admin/dist` 和 `/admin` 路径，本次补齐可直接使用的环境配置、构建验证和部署说明。

### 网页云身份

后台网页先建立 CloudBase 网页端基础身份，再调用 `gym-api`。管理员账号密码仍由 `gym-api` 验证，管理员会话继续保存在当前浏览器会话中。CloudBase 控制台需要允许后台托管域名访问当前环境。

### 访问方式

- 本地测试：运行 `npm run admin:dev` 后打开终端给出的地址。
- 云端测试：静态托管部署完成后，打开 CloudBase 控制台给出的默认域名并访问 `/admin/`。
- 正式上线：部署到正式环境，可继续使用默认域名或绑定自定义域名。

## 测试环境与正式环境

### 当前测试环境

- 环境编号：`cloud1-d1gmh1lu77f6e8c06`
- 使用真实云数据库、云函数、云存储和静态网站托管。
- 尽量使用 CloudBase 免费额度，不自动购买或扩容资源。
- 微信手机号能力不属于 CloudBase 免费额度；测试前在微信公众平台确认当前体验额度，系统仅在用户首次主动登录或主动更新手机号时调用。
- 测试支付与真实微信支付由环境配置选择。测试环境可以使用明确标注的测试支付，正式环境必须关闭测试支付并配置真实支付服务。

### 迁移正式环境

迁移时只需：

1. 创建正式 CloudBase 环境并部署相同集合、索引和云函数。
2. 设置正式环境编号和服务密钥。
3. 构建并部署同一份小程序与运营后台代码。
4. 关闭测试支付并配置真实微信支付。
5. 配置正式后台域名和权限。

不修改登录、会员、预约、排班、反馈、申诉或后台业务代码。

## 错误处理

- 用户拒绝头像、昵称或手机号授权：保留游客状态并说明可稍后继续。
- 头像上传失败：不创建半完成会员，允许重新上传。
- 手机号凭证失效或已使用：提示重新点击手机号授权。
- 登录创建失败：不丢失当前购买页选择，允许重试。
- 游客直接调用受保护接口：返回明确的“请先登录”，不返回内部错误。
- 后台静态页面无法建立云连接：展示可重试的连接错误，不展示空白页面。

实施时使用测试先行，至少覆盖：

- 游客首次打开不会写入会员。
- 游客可以读取公开课包和教练。
- 只有主动提交授权后才创建会员。
- 同一微信身份重复登录不会重复创建会员。
- 未登录用户不能购买或预约。
- 购买登录后保留课包和教练选择。
- “我的”游客态与登录态展示正确。
- 手机号不能由客户端伪造。
- 小程序和后台主要导航使用图标并保留文字。
- 后台能在 `/admin/` 子路径正确构建。
- 后台建立基础云身份后才能调用管理云函数。
- 测试环境和正式环境的差异只存在于部署配置。

完成后运行全部代码检查、自动化测试、三个云函数构建和运营后台生产构建。根据用户要求，不使用 Playwright 或浏览器自动化测试。

## 完成标准

- 打开小程序不弹授权、不创建默认会员。
- 点击购买或“我的”登录按钮才显示微信授权页面。
- 登录后数据库保存真实头像、昵称和手机号，并能在个人页与后台会员列表中看到。
- 游客浏览和登录后购买流程均可用。
- 主要导航和操作入口完成线性图标替换。
- 运营后台可本地打开，也可部署到当前 CloudBase 环境的 `/admin/`。
- 正式迁移只需更换环境配置和外部服务密钥。
